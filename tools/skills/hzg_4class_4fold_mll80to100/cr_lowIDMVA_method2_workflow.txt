HZγ ttH 4-class v3 — CR_lowIDMVA 方法二 (control region background estimate) Workflow
========================================================================================
更新日期: 2026-11-03

本文件记录 v3 (Mll80to100) 4-class 分析里"方法二"(用 CR_lowIDMVA data 做
data-driven 背景估计) 的数据准备 / 推理 / 检查 / Z 流程。
前提: nominal MC + nominal Data 的 merge / pt_only / 4-fold inference 已全部完成,
本流程不重训、不重处理 MC 和 nominal Data, 只新处理 CR Data。

方法二的核心(用户定义):
  1. 拿 CR data 的 mass 形状          ← CR_lowIDMVA__<cat>    (CR SR 区, source_tree_tag 0-4)
  2. 用 sideband 积分比把 CR scale 到对齐 nominal sideband data
       alpha = N_Data_SB / N_CR_SB     ← N_CR_SB 来自 CR_lowIDMVA_SB__<cat> (source_tree_tag 5-9)
                                        N_Data_SB 来自 nominal merged_SR_Sideband (source_tree_tag 奇)
  3. 取 120-130 的 scale 后 CR data 作为本底事例数
       B_CR_SR = alpha × N_CR_SR
  GNN 4-class score 在第 4 步检查 + 最终 Z 里用来把事件划进 signal-enriched 区域,
  但核心 transfer factor alpha 本身不依赖 GNN。

    ttHhad/ttHlep/VH3l 单 era 个位数事件 → SB 积分要全 era 合并才有统计。

四、Step3 推理(4 fold, 复用 nominal 训练模型)
----------------------------------------------
和 nominal Data 推理完全同策略: 每个 fold 模型对所有 CR 事件打分(不按 fold 切事件),
下游按 photon_eta_fold % 4 选 OOF 分数(parity k 的事件用 fold{k} 的分数,
即没见过它的模型)。所以 CR 也要 4 个 fold 目录, 不能只 1 个。

提交:
  sbatch DGL/jobs/inference/hzg_cr_lowIDMVA_ttH_4class_4fold_inference_fold0.sbatch
  sbatch DGL/jobs/inference/hzg_cr_lowIDMVA_ttH_4class_4fold_inference_fold1.sbatch
  sbatch DGL/jobs/inference/hzg_cr_lowIDMVA_ttH_4class_4fold_inference_fold2.sbatch
  sbatch DGL/jobs/inference/hzg_cr_lowIDMVA_ttH_4class_4fold_inference_fold3.sbatch
  4 fold 可并行(GPU 独立), 每个跑 11 era。

输出: root_p2root_v3_cr_pt_only_scored_ttH_4class_4fold_fold<k>/Data/Data/<era>.root
  分支 ttH_gnn_score = vector<float>(4 个 class 的 softmax), 和 nominal 同名同结构。
  ttH class 是 index 1(label 约定 bkg=0 ttH=1 VH=2 ggF+VBF=3)。

验证(推理后):
  - 11 个输出文件齐, 事件数和 pt_only 一致(818 等)
  - source_tree_tag 0-9 都在, SR/SB 计数不变
  - ttH_gnn_score 有限, range 合理


五、Step4 检查 + 方法二 Z(diag_cr_lowIDMVA_v3.py)
-------------------------------------------------
  $PYTHON tools/diag_cr_lowIDMVA_v3.py                 # pre-GNN transfer factor
  $PYTHON tools/diag_cr_lowIDMVA_v3.py --score-cut 0.5 # 加 GNN score>0.5 的版本

  读 CR 4 fold scored + nominal Data 4 fold scored, 按 OOF 选分(parity k→fold{k}),
  对每个 cat 报告:
    - CR_SR / CR_SB / Nom_SB 事件数(pre-GNN 和 GNN cut 后两版)
    - alpha = Nom_SB / CR_SB
    - B_CR_SR = alpha × CR_SR (+ 统计误差)
    - score 分布 sanity(有限/range)
  mass 窗口: SR 120-130, SB 110-120 ∪ 130-180(和 v2 diag_cr_counts_v2.py 一致)。
  输出 tools/results_cr_lowIDMVA_v3/cr_lowIDMVA_v3_diag.txt。

  ★ nominal 的 source_tree_tag 是 SR/SB 交替(偶=SR, 奇=SB, tag//2 = cat index),
    CR 的 source_tree_tag 是按 region 分组(0-4 SR, 5-9 SB)。diag 脚本两边都正确处理了,
    不要混用。

  检查重点(用户列的):
    - 5 cat 的 CR SR / CR SB 事件数
    - 4 分类 score 分布(CR vs nominal 对比, 看 transfer factor 方法是否自洽)
    - GNN 各分类区域事件数(加 --score-cut 看 high-score 区)
  之后再进 transfer factor + Z 的最终计算(可基于 significance_4fold.py 改,
   把 B 从 MC counting 换成 B_CR_SR)。

七、关键设计决策(已和用户确认)
------------------------------

  - 推理复用 nominal 4 fold 训练模型, 不重训; CR 单独 config 只为改 tree_name
  - OOF 选分策略和 nominal 完全一致(parity k → fold{k} 分数)
  - nominal Data / MC 已完成的 pipeline 不动
